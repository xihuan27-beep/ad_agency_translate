## 1. 결론

**공개 리뷰 0건 / 사이트 표시 826건, 수집률 0%.** 리뷰 본문이 없으므로 '깊이' 집계, 맥락 분류, 평점 비교 모두 **산출할 수 없습니다.** 지시에 따라 우회하지 않았고, 빈 결과를 그대로 보고합니다.

`reviews/serf_reviews.csv`에는 헤더만 있습니다. 분석 파이프라인은 준비되어 있고 합성 데이터 4건으로 동작을 확인했지만, 합성 데이터와 그 결과는 산출물에 넣지 않았습니다.

## 2. 왜 0건인가

### 2-1. robots.txt (2026-11-23 확인)

| 대상 User-agent | `/search` | `/reviews` | `/community` |
|---|---|---|---|
| `*` (일반 크롤러·스크립트) | 차단 (`Disallow: /`) | 차단 | 차단 |
| `Claude-User`, `Claude-SearchBot` 등 AI 에이전트 | 허용 | **차단** | **차단** |

- 파일 상단 선언: `Content-Signal: search=yes, ai-input=yes, ai-train=no`
- 사이트는 AI 에이전트에게 검색 결과 페이지는 열어두고, **리뷰와 커뮤니티 상세는 명시적으로 막았습니다.** 리뷰를 구조적으로 가져가지 말라는 의사가 분명합니다.
- 그래서 사용자가 지시한 1회성 조회로 보아 `Claude-User` 규칙을 적용했고, 허용된 `/search` 페이지만 요청했습니다. 요청 간격은 1.5초였고 403/429 응답은 없었습니다.

### 2-2. 페이지 자체의 리뷰 가드

검색 페이지에 포함된 데이터(`__NEXT_DATA__`)는 다음과 같습니다.

| 항목 | 값 |
|---|---|
| `reviewTotalLength` | 826 |
| `reviews` (실제로 내려온 리뷰 배열) | **0건** |
| `isReviewGuardActive` | `true` |
| 화면 문구 | "로그인하고 보기", "로그인하면 실제로 방문한 분…" |

리뷰 본문은 서버에서부터 빠진 채로 내려옵니다. 블러 처리된 텍스트가 HTML 안에 숨어 있는 구조도 아닙니다. 따라서 로그인하지 않고 얻을 수 있는 리뷰 텍스트는 없습니다.

### 2-3. 하지 않은 것

- 로그인, 쿠키 주입, 앱 API 직접 호출, `/reviews/{id}` 상세 요청을 하지 않았습니다. robots.txt 위반이자 가드 우회에 해당합니다.
- 공개된 커뮤니티 글로 리뷰를 대체하지 않았습니다. 검색 페이지에는 커뮤니티 글 3건의 일부만 노출되고 전체는 316건입니다. 커뮤니티 글은 리뷰가 아닌 데다 "어디 잘해요?" 같은 질문이라 시술 경험이 아닙니다. `/community` 경로도 robots.txt로 막혀 있습니다.
- 닉네임·유저ID·사진은 수집하지 않았습니다. 수집기는 코드 단계에서부터 이 필드들을 읽지 않습니다(`to_row`).

## 3. 분석 설계 (데이터 확보 시 그대로 적용)

### 3-1. 3단계 집계 정의

| 단계 | 정규식 | 비고 |
|---|---|---|
| (a) 정확 일치 | `깊이(?!감)` | '깊이감'은 (b)로 넘겨 이중 집계를 막음 |
| (b) 어근 변형 | `깊게\|깊은\|깊숙이\|깊이감\|깊어` | '깊어'는 깊어서·깊어진 등을 포함 |
| (c) 반대 표현 | `얕게\|얕은` | |
| 진단용 | `깊(?!이\|게\|은\|숙이\|어)[가-힣]` | 깊고·깊다·깊지·깊었 등 **지정 목록 밖** 형태. 집계하지 않고 누락 규모만 따로 보고 |

- 단위: 등장 횟수와 해당 리뷰 수를 둘 다 냅니다. 비율은 해당 리뷰 수 ÷ 전체 수집 리뷰 수입니다.

### 3-2. 맥락 분류 기준

등장 문장을 먼저 보고, 근거가 없을 때만 앞뒤 1문장까지 봅니다. 위에서부터 처음 맞는 규칙을 채택합니다.

| 순위 | 맥락 | 판정 근거(같은 문장 안) | 예 |
|---|---|---|---|
| 1 | 시술과 무관한 관용 표현 | 깊이/깊은 + 감사·반성·고민·생각·공감·신뢰·인상 | "깊이 감사드립니다" |
| 2 | 통증과 연결 | 아프·아팠·통증·따끔·욱신·뜨거·마취 | "깊게 들어와서 아팠다" |
| 3 | 의료진 설명/조절 | 조절·맞춰·설명·원장·선생님·실장·상담·세팅 | "깊이 조절해주셨다" |
| 4 | 깊은 주름/처짐(시술 전 고민) | 주름·처짐·팔자·고랑·심술보·불독·패인 | "팔자가 깊어서" |
| 5 | 시술/에너지가 깊이 들어감(효과 체감) | 들어가·전달·닿·근막·SMAS·진피·층·효과·느낌·탄력 | "깊이 들어가는 느낌" |
| 6 | 기타 | 위 어디에도 해당 없음 | |

- 통증을 효과보다 먼저 판정합니다. "깊게 들어와서 아팠다"에는 효과 단서('들어와')와 통증 단서가 함께 있는데, 사용자가 이 문장을 통증 예시로 지정했기 때문입니다.
- 앞뒤 문장에서만 근거가 나온 건과 기타로 분류된 건은 `needs_review=True`로 표시해 사람이 최종 판정하도록 했습니다. 규칙 분류는 1차 분류일 뿐입니다.
- 긍정/부정은 평점을 우선합니다(4 이상 긍정, 2 이하 부정). 평점이 3이거나 없으면 같은 구간의 어휘(만족·추천 vs 후회·효과 없음)로 판정합니다.

## 5. 설계 자체에 대한 검토: 데이터를 확보하기 전에 답해야 할 질문

1. **'깊이'는 품사가 둘입니다.** 명사("깊이 조절")와 부사("깊이 들어간다")를 (a)에 함께 넣으면 '의료진 설명'과 '효과 체감'이 같은 단계로 집계됩니다. (a)를 품사별로 나눌지, 맥락 분류로 충분하다고 볼지 정해야 합니다.
2. **(b) 목록이 자의적입니다.** 깊고·깊다·깊지·깊었는데 같은 흔한 활용형이 빠져 있습니다. 진단용 카운트로 누락 규모를 보고하도록 했지만, 누락이 크면 (b)의 비율은 과소 추정됩니다. 목록을 유지할 이유가 있습니까?
3. **(c)는 (a)·(b)의 대칭이 아닙니다.** '얕게'는 "얕게 들어가서 안 아팠다"(긍정)처럼 쓰일 수도 있고 "얕게만 들어가 효과 없다"(부정)처럼 쓰일 수도 있습니다. 맥락 분류 없이 횟수만 보면 '반대 표현'이라는 가정이 검증되지 않습니다. (c)에도 맥락 분류를 적용할지 결정이 필요합니다.
4. **평점 기반 긍정/부정은 왜곡될 수 있습니다.** 시술 리뷰 평점은 대개 상위에 몰려 있습니다. 실제 분포를 보기 전에는 '긍정 비율'이 변별력을 가질지 알 수 없습니다. 이벤트성 리뷰가 섞여 있다면 더 그렇습니다(검색 페이지에 '리뷰 이벤트' 동의 항목이 있습니다).
5. **'깊이' 언급률이 높은 것이 무엇을 뜻합니까?** 시술의 실제 특성일 수도 있고, 병원이나 광고 문구("깊은 층까지")를 리뷰어가 따라 쓴 결과일 수도 있습니다. 광고·번역 업무 목적이라면 후자가 오히려 핵심 질문일 수 있으니, 분석 목적을 먼저 정해야 합니다.
